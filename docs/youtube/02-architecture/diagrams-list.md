## 📊 Диаграмма 1: Проблема сложности

### Содержание
```
Рост сложности в Enterprise системах

Простой проект          Enterprise система
┌─────────────┐        ┌─────────────────────────┐
│ 1 файл      │   →    │ 50,000+ строк кода      │
│ 1 функция   │        │ 20 таблиц БД            │
│ 1 разработчик│        │ 15+ интеграций          │
│ Локальный   │        │ 10+ разработчиков       │
└─────────────┘        │ 24/7 availability       │
                       └─────────────────────────┘

Проблемы:
❌ Все связано со всем
❌ Невозможно тестировать
❌ Изменения ломают систему
❌ Новички не разбираются
```

### Визуальные элементы
- Схема роста сложности (стрелка вверх)
- Красные крестики для проблем
- Контраст простого vs сложного

## 📊 Диаграмма 2: DDD Принципы

### Содержание
```
Domain-Driven Design

🗣️ Ubiquitous Language
   Единый язык команды и кода
   
   NewsArticle — interface + isStale() ✅
     // не класс с canBeArchived() ❌

🏛️ Bounded Context
   Четкие границы ответственности
   
   News Context     Weather Context
   ┌─────────────┐  ┌─────────────┐
   │ Articles    │  │ Forecasts   │
   │ Sources     │  │ Locations   │
   │ Clusters    │  │ Alerts      │
   └─────────────┘  └─────────────┘

📐 Domain Model
   Модель предметной области
   
   Article → Cluster → Feed
   
🏗️ Layered Architecture
   Изоляция слоев ответственности
```

### Визуальные элементы
- Иконки для каждого принципа
- Примеры кода
- Схемы контекстов

## 📊 Диаграмма 3: Четыре слоя архитектуры

### Содержание
```
Layered Architecture

┌─────────────────────────────────────────┐
│           API Layer                     │  HTTP, валидация
│  /api/news, /api/admin, /api/weather    │  WebSocket, роуты
└─────────────────────────────────────────┘
              ↓ зависит от
┌─────────────────────────────────────────┐
│       Application Layer                 │  Use Cases
│  CollectNewsUseCase, ClusterNewsUseCase │  Оркестрация
└─────────────────────────────────────────┘
              ↓ зависит от
┌─────────────────────────────────────────┐
│      Infrastructure Layer               │  Внешние системы
│  PostgreSQL, Redis, NER, RSS парсер     │  Кэш, БД, API
└─────────────────────────────────────────┘
              ↓ зависит от
┌─────────────────────────────────────────┐
│         Domain Layer                    │  Бизнес-логика
│  NewsArticle (interface), NewsCluster   │  Чистые функции
└─────────────────────────────────────────┘

Правило: верхние слои зависят от нижних
Domain Layer НЕ ЗНАЕТ о других слоях!
```

### Визуальные элементы
- Цветовое кодирование слоев
- Стрелки зависимостей
- Примеры файлов в каждом слое

## 📊 Диаграмма 4: Проблема сильной связанности

### Содержание
```
Антипаттерн: Прямые вызовы

CollectNewsUseCase
       │
       ├─→ CacheService.invalidate()
       ├─→ WebSocketManager.broadcast()
       ├─→ PushService.sendToAll()
       ├─→ ClusterService.updateClusters()
       └─→ AlertManager.checkThresholds()

Проблемы:
❌ CollectNewsUseCase знает о всех потребителях
❌ Сложно добавить новые обработчики  
❌ Невозможно тестировать изолированно
❌ Изменение одного ломает другое
❌ Циклические зависимости

Решение: EventBus! →
```

### Визуальные элементы
- Схема с множественными стрелками
- Красные крестики для проблем
- Стрелка к решению

## 📊 Диаграмма 5: EventBus решение

### Содержание
```
EventBus: Слабая связанность

Publisher                    EventBus                    Subscribers
┌─────────────────┐         ┌─────────┐         ┌─────────────────────┐
│CollectNewsUseCase│────────→│ events  │────────→│ CacheService        │
│                 │         │         │         │ WebSocketManager    │
│ emit('articles. │         │ routing │         │ PushService         │
│ collected', data)│         │         │         │ ClusterService      │
└─────────────────┘         └─────────┘         │ AlertManager        │
                                                └─────────────────────┘

Преимущества:
✅ Publisher не знает о Subscribers
✅ Легко добавлять новые обработчики
✅ Простое тестирование (mock EventBus)
✅ Горизонтальное масштабирование
✅ Нет циклических зависимостей
```

### Визуальные элементы
- Схема pub/sub
- Зеленые галочки для преимуществ
- Стрелки событий
