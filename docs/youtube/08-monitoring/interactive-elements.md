## 🎯 Вызовы

### Вызов 1: Promise.allSettled vs Promise.all
**Время:** После объяснения HealthMonitoringService (9 минута)

```
🤔 Вопрос:

HealthMonitoringService использует Promise.allSettled.
Что произойдёт если Redis недоступен при Promise.all?

A) Получим статус всех 4 компонентов
B) Получим исключение, статус DB и NER неизвестен
C) Redis проверка пропустится, остальные выполнятся
D) Таймаут 5 сек, потом получим все статусы

Пишите ответ в комментариях! 👇
```

**Правильный ответ:** B — Promise.all бросает исключение при первой ошибке. Promise.allSettled возвращает результат для каждого промиса независимо.

### Вызов 2: Percentiles
**Время:** После объяснения p50/p95/p99 (14 минута)

```
📈 Посчитайте p95 для /api/news:

10 запросов (отсортированы):
  12, 15, 18, 22, 45, 67, 89, 120, 180, 4800 ms

Среднее: 537ms
p50 (медиана): ?
p95: ?

Порог SLA: 500ms
SLA выполняется?

Подсказка: p95 = значение на позиции ceil(10 × 0.95) - 1
```

**Правильный ответ:**
- p50 = 45ms (позиция 5 из 10)
- p95 = 4800ms (позиция ceil(9.5)-1 = 9, индекс 9)
- SLA НЕ выполняется: 4800ms > 500ms → violation 'response_time'
- Среднее (537ms) тоже превышает, но p95 честнее показывает проблему

### Вызов 3: Двойной polling
**Время:** После объяснения Zone A (19 минута)

```
⏱️ Zone A использует два интервала:
  setInterval(fetchAll, 30_000)   — данные
  setInterval(fetchSystem, 2_000) — статус коллектора

Почему нельзя использовать один интервал 2 сек для всего?

A) Технически нельзя — ограничение React
B) Слишком много запросов к API — нагрузка на сервер
C) Данные за 24ч не меняются каждые 2 сек
D) WebSocket уже обновляет данные

Что из этого ГЛАВНАЯ причина?
```

**Правильный ответ:** B — 30 запросов в минуту вместо 1. Данные за 24ч меняются медленно, статус коллектора — быстро. Разные данные требуют разных интервалов.
