#### Подблок 1.2: Планировщик (2 минуты)

**[Показать код ScheduleManagementService]**

**Ведущий:**
> У нас два типа расписаний:

```typescript
// Fast источники — каждую минуту (lenta.ru, rbc.ru, habr.com, youtube.com...)
const fastCronExpression = '* * * * *';

// Slow источники — каждые 5 минут (guardian.com, al-jazeera, reuters...)
const slowCronExpression = '*/5 * * * *';
```

**Почему разделение:**
- **Fast** — новостные агентства и популярные ресурсы (высокая частота обновлений)
- **Slow** — зарубежные и тематические ресурсы (реже обновляются)
- **Оптимизация** — не нагружаем источники лишними запросами
- **Из БД** — расписание хранится в `source_config`, меняется без перезапуска

#### Подблок 1.3: Поток данных (2 минуты)

**[Показать sequence диаграмму]**

**Ведущий:**
> Посмотрим как проходит один цикл сбора:

```
1. Cron запускает CollectNewsUseCase
2. Получаем активные источники по расписанию
3. Параллельно парсим RSS каждого источника
4. Валидируем и сохраняем статьи
5. Публикуем событие articles.collected
6. Подписчики обновляют кэш, отправляют уведомления
```

**Время выполнения:**
- Полный цикл: 30-60 секунд
- Парсинг одного источника: 1-3 секунды
- Сохранение в БД: 100-500ms

#### Подблок 2.1: RssParser в действии (3 минуты)

> Сердце системы — функция `parseSourceFeed`. Посмотрим как она работает:

```typescript
const parserLenient = new Parser({ timeout: 5000, xml2js: { strict: false } });

  try {

  } catch (err) {
    if (isXmlError(err)) {

    } else {
      throw err; // сетевые ошибки — наверх
    }
  }

  // Максимум 50 статей за цикл
  for (const item of feed.items.slice(0, 50)) {
    // Специальная логика для rbc.ru, telegram, youtube...
  }
}
```

**Ключевые особенности:**
- **Функция, не класс** — без состояния, легко тестировать
- **Таймаут 5 секунд** — жёсткий лимит на уровне парсера
- **Retry логика** — в `RssCollectionService` через `withTimeout` (8 сек)
- **Один парсер** обрабатывает RSS, Telegram и YouTube — тип источника определяет логику

#### Подблок 3.2: Система алертов (3 минуты)

**[Показать код AlertManager]**

**Ведущий:**
> AlertManager работает **независимо** от цикла сбора — проверяет условия каждые 30 секунд:

```typescript
// Правила, связанные с RSS:
const rssRules = [
  {
    id: 'rss-collection-stalled',
    severity: 'critical',
    cooldownMinutes: 15,
    // Нет сбора > 30 минут
    condition: (metrics) =>
      Date.now() - metrics.lastCollectedAt.getTime() > 30 * 60 * 1000,
  },
  {
    id: 'high-error-rate',
    severity: 'warning',
    cooldownMinutes: 10,
    // > 50% источников с ошибками
    condition: (metrics) =>
      metrics.sourcesWithErrors / metrics.totalSources > 0.5,
  },
  {
    id: 'rate-limit-issues',
    severity: 'warning',
    // > 2 домена в backoff
    condition: (metrics) => metrics.backedOffDomains > 2,
  },
];
```

**Каналы уведомлений:**
- **WebSocket** — мгновенные уведомления в кабинет мониторинга
- **Webhook** — критические алерты в Slack/Discord (если `ALERT_WEBHOOK_URL` задан)
- **Log** — структурированное логирование всех событий через Winston

**Пример алерта:**

### Блок 4: Производительность и масштабирование (3 минуты)

#### Подблок 4.1: Оптимизации (2 минуты)

**[Показать метрики производительности]**

**Ведущий:**
> Как мы достигли надёжности при последовательной обработке:

**Последовательная обработка с задержкой:**
```typescript
// Не параллельно — последовательно, 500ms между источниками
const SOURCE_DELAY_MS = 500;

for (const [index, source] of sources.entries()) {
  this.scheduleService.updateCycleProgress(index + 1, source.name);
  
  try {
    const insertedCount = await this.processSource(source);
    totalInserted += insertedCount;
  } catch (error) {
    // Ошибка одного источника не останавливает остальные
    console.error(`Failed to process ${source.name}:`, error);
  }
  
  await this.delay(SOURCE_DELAY_MS);
}
```

**Почему последовательно, а не параллельно:**
- Защита источников от перегрузки
- Предсказуемое потребление памяти
- Простота отладки и мониторинга прогресса

**Rate limiting по домену:**
```typescript
// RssRateLimiter: разные лимиты для разных доменов
// lenta.ru: 30 req/min, burst: 5
// rbc.ru:   20 req/min, burst: 3
// default:  10 req/min, burst: 2
// + exponential backoff при ошибках (Redis + memory)
```
