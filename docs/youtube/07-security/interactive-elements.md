## 🎯 Вызовы

### Вызов 1: CSP директивы
**Время:** После объяснения Content Security Policy (7 минута)

```
🤔 Вопрос:

В CSP проекта есть директива:
  imgSrc: ["'self'", "data:", "https:", "http:", "blob:"]

Зачем http: если у нас HTTPS сайт?

A) Ошибка в конфигурации
B) RSS-источники отдают изображения по HTTP
C) Для совместимости со старыми браузерами
D) Cloudflare конвертирует HTTP в HTTPS

Пишите ответ в комментариях! 👇
```

**Правильный ответ:** B — RSS-ленты часто содержат изображения по HTTP. Убрать `http:` = сломать половину картинок в ленте новостей.

### Вызов 2: DDoS suspiciousScore
**Время:** После объяснения пяти паттернов (14 минута)

```
🔥 Посчитайте suspiciousScore:

IP 1.2.3.4 за последнюю минуту:
  • 150 запросов (>100)
  • User-Agent: "nikto/2.1.6"
  • Запросы к /wp-admin, /.env, /.git

Паттерны и баллы:
  high_frequency  → +30
  suspicious_ua   → +20
  scanning        → +15

Итого: ?
Заблокируют ли этот IP?
(SUSPICIOUS_THRESHOLD = 100)
```

**Правильный ответ:** 65 баллов — НЕ заблокируют сразу. Но если добавится `rapid_sequential` (+20) или `high_errors` (+25) — порог будет превышен.

### Вызов 3: AlertManager cooldown
**Время:** После объяснения 17 правил (21 минута)

```
⏰ Почему у ssl-certificate-expiring
cooldown = 1440 минут (24 часа)?

A) Баг в коде
B) SSL проверяется раз в сутки
C) Защита от спама — алерт раз в день достаточно
D) Ограничение Slack webhook API

Подумайте: что будет без cooldown при
CHECK_INTERVAL_MS = 30 сек?
```

**Правильный ответ:** C — без cooldown за сутки придёт 2880 алертов (86400 / 30). Cooldown 24ч = один алерт в день, пока проблема не решена.
