## 🎯 Вызовы

### Вызов 1: Стратегии кэширования
**Время:** После объяснения четырёх стратегий (8 минута)

```
🤔 Вопрос:

Пользователь открывает статью офлайн.
Какая стратегия обработает запрос /api/news/123?

A) CacheFirst — вернёт из кэша
B) NetworkFirst — попробует сеть, fallback на кэш
C) NetworkOnly — вернёт ошибку
D) Precache — вернёт из precache

Пишите ответ в комментариях! 👇
```

**Правильный ответ:** C — /api/* обрабатывается NetworkOnly.
Офлайн-данные статей берутся из IndexedDB клиентским кодом, не SW.

### Вызов 2: Версионирование Dexie
**Время:** После объяснения схемы NewsDb (13 минута)

```
💾 Что произойдёт с данными пользователя
при обновлении версии Dexie с 2 на 3?

A) Все данные удалятся
B) Данные сохранятся, добавится таблица bookmarks
C) Браузер запросит разрешение на обновление
D) Приложение упадёт с ошибкой

Ответ в комментариях!
```

**Правильный ответ:** B — Dexie добавляет новые таблицы без потери существующих данных.
Исключение: WeatherDatabase v2/v3 явно вызывает `.upgrade(tx => tx.table('hourly').clear())`.

### Вызов 3: Pending Actions
**Время:** После объяснения retry логики (19 минута)

```
📤 Пользователь поставил лайк офлайн.
Попытка отправить на сервер провалилась 3 раза.
Что произойдёт с записью в pendingActions?

A) Удалится автоматически
B) Будет повторяться бесконечно
C) Статус изменится на 'failed', попытки прекратятся
D) Пользователь получит уведомление об ошибке

MAX_RETRIES = 3
```

**Правильный ответ:** C — после 3 неудач статус `failed`, запись остаётся в IDB но больше не обрабатывается.
