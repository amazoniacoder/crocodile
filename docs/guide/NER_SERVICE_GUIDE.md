# NER-сервис — руководство по запуску и настройке

> Версия: 1.1  
> Создан: Май 2025  
> Обновлён: Май 2025

---

## Концепция

Python-микросервис на базе Natasha + pymorphy2. Принимает батч заголовков статей, возвращает именованные сущности (персоны, организации, локации) в нормализованной форме (именительный падеж).

Используется для блока **«Похожие новости»** на детальной странице (`/news/:slug`) — Entity-Driven Cluster.

**Область применения:** все статьи независимо от региона. Английские заголовки Natasha обрабатывает с низким качеством — вернёт пустые массивы, это нормально.

**Окно поиска похожих:** 48 часов (`ENTITY_WINDOW_HOURS` в `EntityClusterService.ts`).

## Запуск локально (без Docker)

### 1. Установить зависимости (один раз)

```bash
cd D:\BlogPro\ner-service
pip install fastapi uvicorn natasha pymorphy2
```

### 2. Запустить сервис (Терминал 1 — держать открытым)

```bash
cd D:\BlogPro\ner-service
uvicorn main:app --host 0.0.0.0 --port 8001
```

Сервис должен быть запущен **всегда пока работает основной сервер** — новые статьи обогащаются сущностями в реальном времени.

### 3. Настроить `.env`

В `D:\BlogPro\.env` убедиться что есть:

```env
NER_SERVICE_URL=http://localhost:8001
```

### 4. Применить миграцию БД (один раз)

```bash
cd D:\BlogPro
npx drizzle-kit migrate
```

Миграция `0009_add_entities.sql` добавляет:
- Колонку `entities JSONB` в `news_articles` с GIN-индексом
- Таблицу `hot_entities` для агрегации топ-100 сущностей за 24ч

## Прогон существующих статей

Запускается **один раз** после первого деплоя чтобы обогатить статьи за последние 7 дней.

```bash
# Терминал 1: NER-сервис должен быть запущен
# Терминал 2:
cd D:\BlogPro
npx tsx scripts/backfill-entities.ts
```

Вывод:
```
✅ Database connection successful
Backfill: 6500 articles to process
50/6500
100/6500
...
Done
```

**Повторный запуск** безопасен — перезапишет entities для всех статей за 7 дней (полезно после обновления NER-модели).

## Проверка работы

### Проверить что сервис отвечает

```bash
curl http://localhost:8001/health
# {"ok":true}
```

### Проверить извлечение сущностей

```bash
curl -X POST http://localhost:8001/extract \
  -H "Content-Type: application/json" \
  -d "{\"texts\": [\"Трамп подписал указ о санкциях против России\"]}"
# [{"PER":["Трамп"],"ORG":[],"LOC":["Россия"]}]
```

### Проверить заполненность в БД

```sql
-- Сколько статей с сущностями и без
SELECT
  COUNT(*) FILTER (WHERE entities IS NOT NULL) AS with_entities,
  COUNT(*) FILTER (WHERE entities IS NULL)     AS without_entities
FROM news_articles
WHERE published_at >= NOW() - INTERVAL '7 days';

-- Примеры заполненных сущностей
SELECT id, title, entities
FROM news_articles
WHERE entities IS NOT NULL
  AND entities != '{"PER":[],"ORG":[],"LOC":[]}'::jsonb
LIMIT 10;
```

## Архитектура Entity-Driven Cluster

### Поток данных при сборе новостей

```
[CollectNewsUseCase]
  → вставка статьи в БД
  → батч по 10 заголовков → POST http://ner-service:8001/extract
  → UPDATE news_articles SET entities = {...} WHERE id = ?
```

При недоступности NER-сервиса статья сохраняется с `entities = null` — это не блокирует сбор.

### Логика подбора «Похожих новостей» (GET /api/news/:id)

```
Шаг 1 — Entity-поиск (окно 48ч):
  Берём все термины из PER + ORG + LOC текущей статьи
  Ищем статьи где совпадают ≥ 2 термина (ILIKE)
  Если нашли ≥ 1 → возвращаем все найденные (без лимита)

Шаг 2 — Cluster fallback:
  Если Шаг 1 пустой и у статьи есть cluster_id
  → берём статьи из того же токенного кластера (без лимита)

Если оба шага пустые → блок «Похожие новости» не отображается

Category fallback — блок «Другие новости»:
  Если Шаги 1 и 2 пустые → 3 свежие статьи из той же категории и региона
  Отображается в отдельном блоке под «Похожими новостями»
```

### Hot Entities Job

Каждый час агрегирует топ-100 сущностей за последние 24ч в таблицу `hot_entities`. Используется для:
- Аналитики в кабинете мониторинга (будущее)
- Подписки на сюжет (будущее)
- Весового ранжирования редких сущностей (будущее)

## Настройка качества

### Окно поиска похожих

В `server/application/news/EntityClusterService.ts`:

```typescript
const ENTITY_WINDOW_HOURS = 48; // 48ч — оптимально для новостного агрегатора
```

48 часов выбрано намеренно: тема живёт в «Похожих новостях» пока актуальна. Увеличение до 7 дней имеет смысл для долгоиграющих тем (санкции, курс валют), но замедляет запрос на большой базе.

### Минимум совпадающих сущностей

```typescript
minMatches: 2  // в findByEntities вызове
```

Снизить до 1 — больше результатов, меньше точность. Повысить до 3 — меньше результатов, выше точность.

### Размер батча NER

В `server/infrastructure/ner/NerService.ts`:

```typescript
const BATCH_SIZE = 10; // 200 статей = 20 HTTP-запросов к NER
```

## Известные особенности и ограничения

- **Аббревиатуры** (США, ВСУ, ЦБ) — сохраняются в верхнем регистре как есть, не склоняются
- **Английские заголовки** — Natasha вернёт пустые массивы, статья получит `entities = {"PER":[],"ORG":[],"LOC":[]}`, попадёт в cluster fallback
- **NER недоступен** — статья сохраняется с `entities = null`, не блокирует сбор, попадёт в cluster fallback на детальной странице
- **Нормализация падежей** — Natasha + pymorphy2 приводят сущности к именительному падежу при извлечении. Поиск через `ILIKE` не учитывает падежи при сравнении — но поскольку все сущности уже нормализованы на этапе сохранения, совпадение происходит корректно. Исключение: статьи обработанные до обновления нормализации (версия 1.0) могут содержать «Трампа» вместо «Трамп» — решается повторным прогоном `backfill-entities.ts`
- **Многословные сущности** — «Шимановский округ» нормализуется пословно, что может давать неточные формы для составных топонимов
- **Омонимия** — «Орёл» (город) и «орёл» (птица) не различаются без контекста; Natasha использует контекст заголовка, но короткие заголовки дают больше ошибок

## Потенциальные улучшения

### 1. Синонимы и алиасы сущностей
Сейчас «Трамп» и «Дональд Трамп» — две разные сущности, совпадения не будет. Решение: таблица `entity_aliases (canonical, alias)` и нормализация при сохранении к canonical-форме.

### 2. Весовое ранжирование через hot_entities
Сейчас все сущности равнозначны. Редкая сущность («Новатэк») сильнее связывает статьи чем частая («Россия»). Таблица `hot_entities` уже собирает `mention_count` — можно использовать для взвешивания: чем ниже `mention_count`, тем выше вес совпадения.

### 3. Настраиваемое окно через source_config
Сейчас `ENTITY_WINDOW_HOURS = 48` — константа в коде. Можно вынести в `source_config` и менять через кабинет мониторинга без перезапуска.

### 4. Кэширование результатов
Сейчас `GET /api/news/:id` не кэшируется — entity-поиск выполняется при каждом запросе. Можно добавить Redis-кэш с TTL 5 минут по ключу `news:similar:{id}`.

### 5. Английские источники
Natasha не работает с английским. Для The Guardian / Al Jazeera / Reuters можно подключить spaCy `en_core_web_sm` в тот же FastAPI-сервис с автоопределением языка заголовка.

### 6. Подписка на сюжет
`hot_entities` как основа: пользователь подписывается на сущность (например «Газпром»), получает уведомление при появлении новых статей с этой сущностью в `entities`.
