# Кабинет мониторинга — Руководство

> Маршрут: http://localhost:3000/admin/monitor  
> Требует: `ADMIN_TOKEN` из `.env`

---

## Вход

Токен вводится один раз и сохраняется в `sessionStorage` — сбрасывается при закрытии вкладки.  
Проверка токена: запрос `GET /api/admin/news/sources`. Если 401 — токен неверный.

## Зона A — Мониторинг (Parser Health)

### Вкладки

| Вкладка | Содержимое |
|---------|-----------|
| Обзор | Сводные карточки + PieChart регионов + ActivityChart |
| Россия | BarChart + таблица только российских источников |
| Мир | BarChart + таблица только зарубежных источников |
| ⚠️ Ошибки | Источники с `errorCount > 0` за 24ч |
| 🚫 Заблокированы | Источники с ошибкой содержащей «Заблокировано» / «503» |

Рядом с каждой вкладкой — счётчик источников. Вкладки «Ошибки» и «Заблокированы» подсвечиваются если счётчик > 0.

В заголовке зоны:
- **N аномальных** — источники у которых `errorCount > 0` или `totalInserted = 0` за 24ч
- **RSSHub** — индикатор доступности локального инстанса (`localhost:1200`): зелёная точка = онлайн, красная = недоступен

### Вкладка «Обзор»

Три кликабельные карточки:

| Карточка | Что показывает |
|----------|---------------|
| Новых статей за 1ч | Количество вставленных статей + процент от всего полученного из RSS. Клик → модальное окно со списком статей |
| Ошибки за 1ч | Суммарное количество ошибок + сколько источников с ошибками. Клик → модальное окно с таблицей ошибок |
| Коллектор | Статус `▶ Работает` / `⏸ Ожидает`, время последнего цикла, `ближайший`, `следующий fast`, `следующий slow`. Клик → переход в Зону B |

Под карточками — два графика рядом:
- **Распределение по регионам (24ч)** — PieChart: 🌍 Мир / 🇷🇺 Россия / 🏙️ Города России
- **Активность сбора по часам (24ч)** — BarChart суммарных статей по часам

### Вкладки «Россия» / «Мир» / «Ошибки» / «Заблокированы»

Горизонтальный BarChart «Статьи по источникам за 24ч» (только для вкладок Россия/Мир):

| Цвет бара | Значение |
|-----------|----------|
| 🟢 Зелёный | ≥ 5 статей — норма |
| 🟡 Жёлтый | < 5 статей — мало |
| 🔴 Красный | 0 статей — источник не отдаёт данные |

### Таблица источников

| Колонка | Описание |
|---------|----------|
| Источник | Название источника |
| Регион | `russia` / `world` |
| Статьи | Количество новых статей за 24ч |
| Latency | Среднее время от публикации до момента сбора (`fetchedAt - publishedAt`). Аномалии (< 0 или > 6ч) отфильтрованы |
| Статус | OK / 0 статей / текст последней ошибки / OFF |
| Последний сбор | Время последнего успешного цикла по источнику |
| Toggle | Переключатель ON/OFF прямо из таблицы |

**Обновление:** каждые 30 сек + мгновенно при получении WS-события `news_updated`.  
Статус коллектора в карточке «Обзора» обновляется каждые **2 сек**.

### Модальное окно «Новые статьи за последний час»

Таблица: Заголовок (ссылка) / Источник / Регион / Категория / Время сбора.  
Данные: `GET /api/admin/monitor/recent-articles?hours=1`.

### Модальное окно «Ошибки за последний час»

Таблица: Источник / Регион / Ошибок / Последняя ошибка / Последний сбор.  
Данные берутся из уже загруженной статистики за 1ч — отдельного запроса нет.

## Зона B — Система (Infrastructure)

### Карточки

| Карточка | Что показывает |
|----------|---------------|
| RSS | Реальное потребление памяти Node.js процессом. Включает V8 (~40-50 МБ базово), все npm пакеты, heap, буферы, нативные биндинги. Подстрока: JS Heap — память занятую объектами JavaScript |
| CPU Load avg | Средняя нагрузка на CPU за 1, 5 и 15 минут. Значение = количество процессов ожидающих CPU. На 4-ядерном CPU нагрузка 4.0 = 100% |
| Uptime сервера | Время работы Node.js процесса без перезапуска. Подстрока: uptime ОС + версия Node.js |
| Цикл сбора | Длительность последнего RSS-цикла в секундах. Если цикл идёт прямо сейчас — показывает живой таймер (`▶` + счётчик секунд), прогресс `N/M` и текущий источник. Подстроки: время завершения последнего цикла, `следующий fast`, `следующий slow` |

### Что значит `следующий fast` и `следующий slow`

- `следующий fast` — ближайший запуск cron для группы **быстрых источников** (`fast_interval_cron`), например `* * * * *`.
- `следующий slow` — ближайший запуск cron для группы **медленных источников** (`slow_interval_cron`), например `*/5 * * * *`.
- `ближайший` — минимальное из двух времен (`fast` и `slow`), то есть самый ближайший реальный авто-запуск коллектора.
- Если вручную запускается `Ручной сбор`, это **не меняет** сами cron-расписания; `fast/slow` остаются плановыми авто-запусками.

### Почему RSS ≠ «память лент»

RSS включает весь процесс целиком. Выделить из него только память занятую RSS-лентами стандартными средствами Node.js невозможно — V8 не маркирует объекты по источнику. Ленты парсятся и освобождаются GC после каждого цикла.

### График «Время цикла сбора»

LineChart последних 50 циклов. Ось Y — секунды. Резкий рост = источник завис или сеть медленная.

**Обновление:** системные метрики каждые 5 сек, график каждые 30 сек.

## Зона C — Управление (Control Room)

Тулбар в заголовке зоны содержит блоки «Интервалы сбора» и «Ручной сбор».

### Таблица источников

Колонки: Название (ссылка на сайт) / Регион / Категория / Город / Последний сбор / Статус (toggle) / Действия.

- **Toggle ON/OFF** — активировать / деактивировать источник прямо в строке
- **✏️** — открыть форму редактирования (название, URL, RSS URL, регион, категория, город)
- **🗑** — деактивировать источник (`PATCH { isActive: false }`). Физически не удаляет — статьи сохраняются
- **+ Добавить** — создать новый источник

**Обновление:** каждые 60 сек + после каждого действия.

### Интервалы сбора

| Ключ | Описание |
|------|----------|
| `fast_interval_cron` | Cron-расписание для быстрых источников |
| `slow_interval_cron` | Cron-расписание для медленных источников |

После нажатия «Применить» — cron-задачи пересоздаются на лету без перезапуска сервера.  
Кнопка «Применить» неактивна пока значение не изменено.

Примеры cron-выражений:
```
* * * * *       — каждую минуту
*/5 * * * *     — каждые 5 минут
*/15 * * * *    — каждые 15 минут
0 * * * *       — каждый час
```

### Ручной сбор

Запускает `CollectNewsUseCase.execute()` немедленно, не дожидаясь cron.  
Показывает время выполнения цикла в секундах.

## Диагностика проблем

**Источник показывает 0 статей:**
1. Проверить toggle — может быть OFF
2. Посмотреть текст в колонке «Статус» — там текст последней ошибки
3. Проверить RSS URL вручную в браузере
4. Запустить ручной сбор и смотреть логи: `grep "📰" logs/combined.log`

**Источник во вкладке «Заблокированы»:**
- Ошибка содержит «Заблокировано» или «503» — источник недоступен с текущего IP
- Деактивировать через toggle или 🗑 чтобы не засорял статистику

**RSSHub показывает красную точку:**
- Локальный инстанс не запущен: `cd D:\RSSHub && npm run dev`
- Источники через `localhost:1200` не будут собираться пока RSSHub офлайн

**Высокий Latency (> 1ч):**
- Источник публикует статьи с неверным `publishedAt` (будущее время или старая дата)
- Аномалии (< 0 или > 6ч) автоматически исключаются из среднего

**RSS растёт со временем:**
- Нормально до ~200 МБ при активном кэше
- Если растёт непрерывно без стабилизации — возможна утечка памяти
- Перезапуск сервера сбрасывает RSS к базовому уровню (~80-100 МБ)

## Zone O — Security Monitoring

### Назначение
Мониторинг безопасности инфраструктуры и проактивные алерты.

### Компоненты

| Компонент | Описание |
|-----------|----------|
| **SSL Certificate Status** | Дни до истечения, издатель, домен, статус валидности |
| **Disk Usage Monitor** | Процент использования, свободное место, тренды потребления |
| **Fail2Ban Statistics** | Активные jail'ы, заблокированные IP, статистика банов за 24ч |
| **Security Alerts History** | Последние 50 алертов безопасности с фильтрацией по severity |
| **Failed Login Attempts** | Статистика неудачных попыток входа в админ-панель |
| **DDoS Protection Status** | Статус защиты, заблокированные IP, подозрительная активность |

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/admin/monitoring/ssl-status` | Статус SSL сертификата |
| GET | `/api/admin/monitoring/disk-usage` | Использование дискового пространства |
| GET | `/api/admin/monitoring/fail2ban-status` | Статистика Fail2Ban |
| GET | `/api/admin/alerts/security` | История алертов безопасности |
| GET | `/api/admin/security/ddos-stats` | Статистика DDoS защиты |

### Автоматические алерты

| Алерт | Условие | Severity | Cooldown |
|-------|---------|----------|----------|
| `ssl-certificate-expiring` | SSL истекает через 30 дней | warning | 24 часа |
| `ssl-certificate-critical` | SSL истекает через 7 дней | critical | 6 часов |
| `disk-space-warning` | Диск заполнен на 80% | warning | 1 час |
| `disk-space-critical` | Диск заполнен на 90% | critical | 30 минут |
| `fail2ban-service-down` | Fail2Ban не запущен | critical | 30 минут |
| `fail2ban-high-bans` | >50 банов за 24ч | warning | 1 час |

### Интеграция с AlertManager

Все алерты безопасности интегрированы с единой системой AlertManager:
- **WebSocket уведомления** в реальном времени
- **Webhook интеграция** для критических алертов (Slack/Discord)
- **Redis персистентность** для истории алертов
- **Cooldown периоды** для предотвращения спама

### Мониторинг в реальном времени

| Метрика | Интервал проверки |
|---------|------------------|
| SSL сертификат | 30 секунд |
| Disk usage | 30 секунд |
| Fail2Ban статус | 30 секунд |
| Security алерты | Мгновенно (WebSocket) |

## Комплексная проверка безопасности

Для полной диагностики безопасности системы используйте скрипт:

```bash
./scripts/security-monitor.sh
```

Скрипт проверяет:
- ✅ Статус системных сервисов (nginx, fail2ban, postgresql, redis)
- 🔒 SSL сертификат (дни до истечения, валидность)
- 💾 Использование диска и памяти
- 🛡️ Статус Fail2Ban (активные jail'ы, статистика банов)
- 🌐 Конфигурация Nginx (Cloudflare IP, rate limiting, security headers)
- 🗄️ Безопасность БД (listen_addresses, статус бэкапов)
- 📊 Анализ логов безопасности (auth failures, nginx errors)
- 🚀 Статус приложения NewsAggregator
