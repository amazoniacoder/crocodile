# Cluster Testing in Admin Panel\n\n## Overview\n\nThe admin panel now includes comprehensive cluster testing functionality accessible through two new zones:\n\n- **🏥 Кластер (Zone F)**: Real-time cluster health monitoring\n- **🧪 Тесты (Zone G)**: Interactive cluster testing suite\n\n## Zone F: Cluster Health Dashboard\n\n### Features\n- **Real-time Health Monitoring**: Live updates every 15 seconds\n- **Node Status Overview**: Visual indicators for each cluster node\n- **Failover Management**: Manual failover triggers and policy configuration\n- **Service Health Checks**: Database, Redis, RSS, and WebSocket status\n- **Performance Metrics**: CPU, memory, connections, and response times\n\n### Usage\n1. Navigate to **🏥 Кластер** in the admin panel\n2. View cluster overview cards showing total/healthy/degraded/unhealthy nodes\n3. Monitor individual node details including:\n   - System metrics (CPU, memory, uptime)\n   - Service status (DB, Redis, RSS, WebSocket)\n   - Active connections and response times\n   - Error messages and diagnostics\n4. Trigger manual failover if needed:\n   - Click \"🔄 Failover\" on any unhealthy node\n   - Provide reason for failover\n   - Confirm execution\n\n## Zone G: Cluster Test Runner\n\n### Available Test Suites\n\n#### 🏥 Health Tests\nTests cluster health monitoring and core services:\n- Health monitoring system status\n- Redis cluster coordination\n- Database connectivity\n- WebSocket service functionality\n- RSS collection service readiness\n\n#### 🔄 Failover Tests\nTests automatic failover and recovery systems:\n- Failover controller status and configuration\n- Distributed locks functionality\n- Node discovery and cluster coordination\n- Failover history and event tracking\n\n#### ⚖️ Load Balancing Tests\nTests load distribution and balancing:\n- Load balancer configuration\n- RSS collection task distribution\n- WebSocket connection distribution\n- Load balancing decision algorithms\n\n#### 🧪 Comprehensive Tests\nRuns all test suites and provides overall summary:\n- Executes all individual test suites\n- Provides consolidated results\n- Shows overall pass/fail statistics\n- Recommended for complete system validation\n\n### Using the Test Runner\n\n1. **Navigate to Zone G**: Click **🧪 Тесты** in the admin panel\n\n2. **Select Test Suite**: Choose from available test types:\n   - Individual test suites for specific components\n   - Comprehensive tests for full validation\n\n3. **Run Tests**: Click on desired test button\n   - Tests run automatically in the background\n   - Progress indicator shows test execution\n   - Results appear in real-time\n\n4. **Review Results**: Examine test outcomes:\n   - ✅ **Success**: Test passed successfully\n   - ⚠️ **Warning**: Test passed with warnings\n   - ❌ **Error**: Test failed\n   - ⏭️ **Skipped**: Test was skipped\n\n5. **View Details**: Expand test results for detailed information:\n   - Click \"View Details\" to see technical data\n   - JSON formatted details for debugging\n   - Performance metrics and timing information\n\n### Test Result Interpretation\n\n#### Success Indicators\n- All services responding correctly\n- Cluster coordination working\n- Load balancing functioning\n- No critical errors detected\n\n#### Warning Indicators\n- Services working but with degraded performance\n- Redis unavailable (single-node mode)\n- High resource usage\n- Non-critical configuration issues\n\n#### Error Indicators\n- Critical services unavailable\n- Database connection failures\n- Cluster coordination broken\n- System-level errors\n\n## API Endpoints\n\nThe testing system uses these admin API endpoints:\n\n```\nPOST /api/admin/cluster/test/health\nPOST /api/admin/cluster/test/failover\nPOST /api/admin/cluster/test/load-balancing\nPOST /api/admin/cluster/test/comprehensive\n```\n\nAll endpoints require admin authentication via Bearer token.\n\n## Troubleshooting\n\n### Common Issues\n\n**Redis Connection Warnings**\n- Normal in single-node deployments\n- Cluster features will be limited\n- Consider Redis setup for full functionality\n\n**Failover Controller Disabled**\n- Check failover policy configuration\n- Verify minimum healthy nodes requirement\n- Review cooldown and rate limiting settings\n\n**High Resource Usage**\n- Monitor CPU and memory metrics\n- Consider scaling if consistently high\n- Check for memory leaks or performance issues\n\n**WebSocket Connection Issues**\n- Verify WebSocket service is running\n- Check for proxy configuration problems\n- Review sticky session setup\n\n### Best Practices\n\n1. **Regular Testing**: Run comprehensive tests weekly\n2. **Monitor Trends**: Watch for degrading performance over time\n3. **Proactive Maintenance**: Address warnings before they become errors\n4. **Documentation**: Keep track of test results and system changes\n5. **Alerting**: Set up external monitoring based on test results\n\n## Integration with Monitoring\n\nThe cluster testing integrates seamlessly with existing monitoring:\n\n- **Zone A**: RSS collection and source health\n- **Zone B**: System infrastructure metrics\n- **Zone C**: Manual control and configuration\n- **Zone F**: Cluster-specific health monitoring\n- **Zone G**: Interactive testing and validation\n\nThis provides a complete picture of system health from RSS collection through cluster coordination to user-facing services.\n\n## Security Considerations\n\n- All cluster testing requires admin authentication\n- Test results may contain sensitive system information\n- Manual failover operations are logged and audited\n- Access should be restricted to authorized administrators only\n\n## Performance Impact\n\nCluster tests are designed to be lightweight:\n\n- Health tests: ~100-500ms execution time\n- Failover tests: ~200-800ms execution time\n- Load balancing tests: ~150-600ms execution time\n- Comprehensive tests: ~500-2000ms execution time\n\nTests can be run safely in production environments without significant performance impact.
