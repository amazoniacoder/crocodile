# Personal Feed Guide

> Руководство по системе личных кабинетов  
> Версия: 1.0  
> Дата: Май 2025

---

## Обзор

Personal Feed — система персональных лент новостей с доступом по токену. Пользователь получает анонимный токен (через подписку на Boosty), выбирает интересующие Telegram/YouTube каналы и видит только их в своей ленте.

**Ключевые особенности:**
- ✅ Никаких личных данных (email, имя, телефон)
- ✅ Токен = анонимный идентификатор кабинета
- ✅ Пользователь сам управляет подписками
- ✅ Админ контролирует токены и может видеть подписки
- ✅ Токены с опциональным сроком действия

## Архитектура

### База данных

**Таблица `user_tokens`:**
```sql
id              SERIAL PRIMARY KEY
token           VARCHAR(64) UNIQUE NOT NULL  -- формат: ut_<32 hex bytes>
label           VARCHAR(255)                 -- метка для админа
is_active       BOOLEAN DEFAULT true
created_at      TIMESTAMP DEFAULT NOW()
expires_at      TIMESTAMP                    -- опционально
last_used_at    TIMESTAMP                    -- обновляется при каждом запросе
```

**Таблица `user_channel_subscriptions`:**
```sql
id              SERIAL PRIMARY KEY
token_id        INTEGER REFERENCES user_tokens(id) ON DELETE CASCADE
source_id       INTEGER REFERENCES news_sources(id) ON DELETE CASCADE
subscribed_at   TIMESTAMP DEFAULT NOW()
UNIQUE(token_id, source_id)
```

### API Endpoints

#### Публичные (`/api/my`)

| Метод | Путь | Описание | Rate Limit |
|-------|------|----------|------------|
| GET | `/validate?token=ut_...` | Проверка валидности токена | 120 req/мин |
| GET | `/feed?token=ut_...` | Персональная лента | 120 req/мин |
| GET | `/available-channels?token=ut_...` | Список доступных каналов | 120 req/мин |
| GET | `/subscriptions?token=ut_...` | Текущие подписки | 120 req/мин |
| POST | `/subscriptions?token=ut_...` | Обновить подписки | 120 req/мин |

#### Admin (`/api/admin/user-tokens`)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/` | Список всех токенов |
| POST | `/` | Создать токен |
| PATCH | `/:id` | Обновить токен (label, isActive, expiresAt) |
| DELETE | `/:id` | Удалить токен (каскадно удаляет подписки) |
| GET | `/:id/subscriptions` | Подписки конкретного токена |
| POST | `/:id/subscriptions` | Управление подписками от имени пользователя |
| GET | `/stats` | Статистика (активных токенов, всего подписок) |

## Для администратора

### Создание токена

**Через админку (Zone N):**

1. Откройте кабинет мониторинга → Zone N (User Tokens)
2. Вкладка "Токены"
3. Заполните форму:
   - **Метка** — например, "Подписчик Boosty #123"
   - **Срок действия** (опционально) — дата истечения токена
4. Нажмите "Создать"
5. Скопируйте токен (кнопка "Копировать" в таблице)
6. Отправьте токен подписчику

**Через API:**

```bash
curl -X POST http://localhost:5000/api/admin/user-tokens \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "label": "Подписчик Boosty #123",
    "expiresAt": "2025-12-31T23:59:59Z"
  }'
```

Ответ:
```json
{
  "token": {
    "id": 1,
    "token": "ut_a1b2c3d4e5f6...",
    "label": "Подписчик Boosty #123",
    "isActive": true,
    "createdAt": "2025-05-15T10:00:00Z",
    "expiresAt": "2025-12-31T23:59:59Z",
    "lastUsedAt": null
  }
}
```

### Управление токенами

**Деактивация токена:**

```bash
curl -X PATCH http://localhost:5000/api/admin/user-tokens/1 \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"isActive": false}'
```

**Продление срока действия:**

```bash
curl -X PATCH http://localhost:5000/api/admin/user-tokens/1 \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"expiresAt": "2026-12-31T23:59:59Z"}'
```

**Удаление токена:**

```bash
curl -X DELETE http://localhost:5000/api/admin/user-tokens/1 \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

⚠️ **Внимание:** При удалении токена все подписки пользователя удаляются каскадно.

### Управление подписками пользователя

**Через админку:**

1. Zone N → вкладка "Токены"
2. Найдите токен в таблице
3. Кликните на число в колонке "Подписки"
4. Откроется модалка со списком каналов
5. Выберите/снимите галочки
6. Нажмите "Сохранить"

**Через API:**

```bash
# Получить текущие подписки
curl http://localhost:5000/api/admin/user-tokens/1/subscriptions \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# Обновить подписки
curl -X POST http://localhost:5000/api/admin/user-tokens/1/subscriptions \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sourceIds": [12, 34, 56]}'
```

### Статистика

**Через админку:**

Zone N → вкладка "Статистика"

**Через API:**

```bash
curl http://localhost:5000/api/admin/user-tokens/stats \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Ответ:
```json
{
  "activeTokens": 15,
  "totalTokens": 20,
  "totalSubscriptions": 87
}
```

### Мониторинг использования

**Последнее использование токена:**

Поле `last_used_at` обновляется автоматически при каждом запросе пользователя. Проверяйте его в таблице Zone N для выявления неактивных токенов.

**Аудит:**

Все действия с токенами логируются в `admin_audit_log`:
- Создание токена
- Обновление (label, isActive, expiresAt)
- Удаление токена
- Изменение подписок

```bash
curl "http://localhost:5000/api/admin/audit/logs?resource=user_token&limit=50" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

## Для пользователя

### Получение доступа

1. Оформите подписку на [Boosty](https://boosty.to/crocodile)
2. Получите токен от администратора (через личку Boosty или email)
3. Токен имеет формат: `ut_a1b2c3d4e5f6...` (67 символов)

### Первый вход

**Вариант 1: Переход по ссылке**

Администратор отправляет ссылку:
```
http://localhost:3000/my?token=ut_a1b2c3d4e5f6...
```

ℹ️ **Совет:** В админке Zone N → Токены → кнопка 🔗 (копировать ссылку) автоматически генерирует правильную ссылку с текущим доменом.

1. Перейдите по ссылке
2. Токен автоматически сохранится в браузере
3. Вы будете перенаправлены на `/my` (без токена в URL)

**Вариант 2: Ручной ввод**

1. Откройте https://crocodile.ru/my
2. Введите токен в форму
3. Нажмите "Войти"

### Управление подписками

1. На странице `/my` нажмите "Управление подписками"
2. Откроется модалка со списком доступных каналов
3. Выберите интересующие каналы (Telegram/YouTube)
4. Нажмите "Сохранить"
5. Лента обновится автоматически

### Просмотр ленты

После выбора каналов вы увидите персональную ленту:
- Только статьи из выбранных каналов
- Сортировка по дате публикации
- Бесконечная прокрутка
- Виртуализация (быстрая работа с большими списками)

### Выход из кабинета

Нажмите кнопку "Выйти" в правом верхнем углу. Токен будет удалён из браузера. Для повторного входа введите токен заново.

### Использование на нескольких устройствах

Токен можно использовать на любом количестве устройств:
- Компьютер
- Телефон
- Планшет

На каждом устройстве токен сохраняется в localStorage браузера независимо.

### Проблемы и решения

**"Токен недействителен или истёк"**

Причины:
- Токен деактивирован администратором
- Истёк срок действия токена
- Токен удалён

Решение: Свяжитесь с администратором для получения нового токена.

**"Нет статей из выбранных каналов"**

Причины:
- Каналы ещё не собраны (новые источники)
- Выбранные каналы неактивны

Решение: Подождите несколько минут или выберите другие каналы.

**"Rate limit exceeded"**

Вы превысили лимит 120 запросов в минуту. Подождите минуту и повторите попытку.

## Технические детали

### Формат токена

```
ut_<32 random bytes in hex>
Пример: ut_a1b2c3d4e5f6789012345678901234567890abcdef1234567890abcdef123456
```

Генерация:
```typescript
import { randomBytes } from 'crypto';
const token = `ut_${randomBytes(32).toString('hex')}`;
```

### Валидация токена

**Серверная валидация:**

1. Проверка формата (`ut_` + 64 hex символа)
2. Поиск в БД (`user_tokens.token`)
3. Проверка `is_active = true`
4. Проверка `expires_at > NOW()` (если задано)
5. Обновление `last_used_at`

**Кэширование:**

Результат валидации кэшируется в Redis на 5 минут:
```
Key: user_token:ut_abc123...
Value: {"valid": true, "tokenId": 1, "expiresAt": "2025-12-31T23:59:59Z"}
TTL: 300 секунд
```

При изменении токена (деактивация, удаление) кэш инвалидируется.

### Rate Limiting

**Механизм:**

- 120 запросов в минуту по токену
- Счётчик в памяти (express-rate-limit)
- Ключ: токен из query или header

**Заголовки ответа:**

```
X-RateLimit-Limit: 120
X-RateLimit-Remaining: 119
X-RateLimit-Reset: 1620000000
```

**Ответ при превышении:**

```json
{
  "error": "Too many requests",
  "message": "Rate limit exceeded. Please try again later."
}
```

### Безопасность

**Хранение токенов:**

- В БД: plaintext (токен сам по себе — секрет)
- В Redis: plaintext (кэш валидации)
- В браузере: localStorage (не httpOnly cookie, т.к. нужен доступ из JS)

**Передача токена:**

- Query parameter: `?token=ut_...` (первый визит)
- Header: `X-User-Token: ut_...` (опционально)

**Защита от брутфорса:**

- Токен: 256 бит энтропии (2^256 вариантов)
- Rate limiting: 120 попыток в минуту
- Время подбора: практически бесконечно

**Аудит:**

Все действия администратора логируются:
- IP-адрес
- User-Agent
- Токен (хэш)
- Действие (CREATE, UPDATE, DELETE)
- Детали (до/после)

## Интеграция с Boosty

### Процесс выдачи токена

1. Пользователь оформляет подписку на Boosty
2. Вы получаете уведомление о новом подписчике
3. Создаёте токен в Zone N с меткой "Boosty #123"
4. Отправляете токен подписчику через:
   - Личные сообщения Boosty
   - Email (если указан)
   - Комментарий к посту (не рекомендуется — токен виден всем)

### Автоматизация (будущее)

Возможна интеграция через Boosty API:
- Webhook при новой подписке → автоматическое создание токена
- Webhook при отмене подписки → деактивация токена
- Периодическая синхронизация активных подписок

## FAQ

**Q: Можно ли использовать один токен на нескольких устройствах?**  
A: Да, токен не привязан к устройству.

**Q: Что происходит при удалении токена?**  
A: Токен и все его подписки удаляются из БД. Пользователь больше не сможет войти.

**Q: Можно ли восстановить удалённый токен?**  
A: Нет, нужно создать новый токен.

**Q: Как узнать, сколько пользователей активны?**  
A: Zone N → Статистика → "Активных токенов". Также смотрите `last_used_at` в таблице.

**Q: Можно ли ограничить количество подписок на токен?**  
A: В текущей версии нет. Можно добавить проверку в `updateTokenSubscriptions`.

**Q: Токен виден в истории браузера?**  
A: Только при первом визите (если переход по ссылке с токеном). После редиректа токен удаляется из URL.

**Q: Можно ли сделать токен одноразовым?**  
A: Да, установите `expires_at` на короткий срок (например, 1 день).

**Q: Как отозвать доступ у пользователя?**  
A: Деактивируйте токен (`isActive = false`) или удалите его.
