# Часть 1: Что такое Prometheus и зачем он нужен

> Простыми словами о системе мониторинга

---

## Что такое Prometheus?

**Prometheus** — это программа, которая **собирает цифры** (метрики) о работе твоего приложения и **хранит их в базе данных**.

Представь, что у тебя есть термометр, который каждые 15 секунд записывает температуру в блокнот. Prometheus делает то же самое, но вместо температуры он записывает:
- Сколько запросов обработал сервер
- Сколько памяти использует приложение
- Сколько статей собрал RSS-парсер
- Как быстро отвечает API

---

## Зачем это нужно?

### Без Prometheus

Ты запускаешь NewsAggregator и видишь в консоли:
```
📰 Collected 42 new articles
```

**Вопросы, на которые ты не можешь ответить:**
- Сколько статей собиралось вчера в это же время?
- Почему сегодня меньше статей, чем обычно?
- Какой источник приносит больше всего статей?
- Сервер тормозит из-за памяти или из-за медленной БД?

### С Prometheus

Ты открываешь http://localhost:9090 и видишь:
- График сбора статей за последнюю неделю
- Сравнение производительности разных источников
- Предупреждение: "Память превышает 500MB уже 10 минут"
- Историю всех проблем за последние 15 дней

---

## Как это работает? (простыми словами)

### Шаг 1: Приложение выставляет метрики

NewsAggregator создаёт специальную страницу `/metrics`:

```
http://localhost:5000/metrics
```

На этой странице — список цифр в текстовом формате:

```
# Сколько статей собрано
rss_articles_collected_total{source="Lenta.ru"} 42

# Сколько памяти использует приложение
nodejs_heap_size_used_bytes 130000000

# Сколько запросов обработано
http_requests_total{method="GET",path="/api/news"} 1523
```

### Шаг 2: Prometheus собирает эти цифры

Каждые 15 секунд Prometheus:
1. Открывает страницу `/metrics`
2. Читает все цифры
3. Записывает их в свою базу данных с текущим временем

Это называется **scraping** (соскребание).

### Шаг 3: Ты смотришь графики

Prometheus хранит все цифры за последние 15 дней (настраивается). Ты можешь:
- Построить график любой метрики
- Сравнить "сейчас" с "вчера"
- Найти момент, когда началась проблема
- Настроить автоматические уведомления

## Ключевые понятия

### Метрика (Metric)

**Метрика** — это одна измеряемая величина с уникальным именем.

Примеры:
- `http_requests_total` — сколько HTTP-запросов обработано
- `nodejs_heap_size_used_bytes` — сколько памяти использует Node.js
- `rss_articles_collected_total` — сколько статей собрано

### Метка (Label)

**Метка** — это дополнительная информация о метрике.

Пример:
```
http_requests_total{method="GET", path="/api/news", status="200"} 1523
```

Здесь:
- `method="GET"` — метод запроса
- `path="/api/news"` — путь
- `status="200"` — статус ответа

Метки позволяют **фильтровать** данные:
- Показать только GET-запросы
- Показать только ошибки (status=500)
- Сравнить разные эндпоинты

### Target (Цель)

**Target** — это адрес, откуда Prometheus собирает метрики.

Пример:
```
http://localhost:5000/metrics
```

У тебя может быть несколько targets:
- NewsAggregator (localhost:5000)
- База данных (localhost:5432)
- Redis (localhost:6379)

### Scrape (Сбор)

**Scrape** — это процесс чтения метрик с target.

По умолчанию происходит каждые **15 секунд**.

### Alert (Алерт)

**Alert** — это правило, которое проверяет условие и уведомляет тебя.

Пример:
```yaml
alert: HighMemoryUsage
expr: nodejs_heap_size_used_bytes > 500000000
for: 10m
```

Это значит: "Если память больше 500MB в течение 10 минут — уведоми меня".

## Prometheus vs Логи

### Логи (Winston, console.log)

**Что:** Текстовые сообщения о событиях

**Пример:**
```
2025-05-06 14:30:15 [INFO] Collected 42 articles from Lenta.ru
2025-05-06 14:30:16 [ERROR] Failed to fetch from Habr
```

**Когда использовать:**
- Нужно понять, **что произошло**
- Нужны детали конкретного события
- Отладка ошибок

**Минусы:**
- Сложно строить графики
- Сложно считать статистику
- Быстро растут в размере

### Метрики (Prometheus)

**Что:** Числовые значения во времени

**Пример:**
```
rss_articles_collected_total{source="Lenta.ru"} 42
rss_collection_errors_total{source="Habr"} 1
```

**Когда использовать:**
- Нужно понять, **как часто** что-то происходит
- Нужны тренды и графики
- Нужны автоматические алерты

**Минусы:**
- Нет деталей конкретного события
- Нельзя увидеть текст ошибки

### Вывод

**Используй оба инструмента:**
- **Prometheus** — для мониторинга и алертов ("Что-то не так!")
- **Логи** — для расследования ("Что именно пошло не так?")

---

## Что Prometheus НЕ делает

❌ **Не хранит логи** — для этого есть ELK, Loki
❌ **Не показывает трейсы запросов** — для этого есть Jaeger, Zipkin
❌ **Не визуализирует красиво** — для этого есть Grafana (опционально)
❌ **Не отправляет уведомления в Telegram** — для этого нужен Alertmanager (опционально)

Prometheus — это **база данных метрик** с простым веб-интерфейсом.

## Prometheus и NewsAggregator

### Что мониторим?

**1. RSS сбор:**
- Сколько статей собрано за час
- Какие источники работают, какие нет
- Как долго длится цикл сбора
- Сколько ошибок при сборе

**2. HTTP API:**
- Сколько запросов в секунду
- Как быстро отвечает API (p50, p95, p99)
- Сколько ошибок 5xx
- Какие эндпоинты самые медленные

**3. Система:**
- Сколько памяти использует Node.js
- Загрузка CPU
- Event loop lag (задержка обработки)
- Garbage collection (сборка мусора)

**4. Бизнес-метрики:**
- Сколько кластеров создано
- Cache hit rate (процент попаданий в кэш)
- Сколько алертов сработало

### Пример реальной пользы

**Ситуация:** Пользователи жалуются, что лента медленно загружается.

**Без Prometheus:**
1. Смотришь логи — ничего подозрительного
2. Перезапускаешь сервер — не помогает
3. Гадаешь: БД? Redis? Код?

**С Prometheus:**
1. Открываешь график `http_request_duration_seconds`
2. Видишь: p95 вырос с 0.1с до 2.5с в 14:30
3. Смотришь график `nodejs_heap_size_used_bytes`
4. Видишь: память выросла с 200MB до 700MB в 14:30
5. **Вывод:** Утечка памяти → медленный GC → медленные запросы
6. Смотришь логи за 14:30 → находишь причину

**Время диагностики:** 5 минут вместо часов.

## Всегда ли Prometheus должен быть запущен?

### Короткий ответ: ДА

Prometheus должен работать **постоянно**, пока работает NewsAggregator.

### Почему?

**1. Prometheus не берёт данные из архива**

Prometheus собирает метрики **в реальном времени** каждые 15 секунд.

Если Prometheus выключен:
- Метрики **не собираются**
- Данные за это время **теряются навсегда**
- Графики будут с пробелами

**2. Алерты не работают без Prometheus**

Алерты проверяются каждые 30 секунд. Если Prometheus выключен — уведомлений не будет.

**3. Исторические данные нужны для анализа**

Чтобы понять, что "сейчас хуже, чем обычно", нужны данные за прошлые дни.

### Как запускать?

**Вариант 1: Вручную (для разработки)**

Запускаешь батник `D:\Prometheus\start-prometheus.bat` — окно остаётся открытым.

**Плюсы:**
- Видишь логи в реальном времени
- Легко остановить (Ctrl+C)

**Минусы:**
- Нужно запускать каждый раз вручную
- Закроешь окно — Prometheus остановится

**Вариант 2: Как Windows Service (для production)**

Prometheus запускается автоматически при старте Windows и работает в фоне.

```cmd
nssm install Prometheus "D:\Prometheus\prometheus.exe"
nssm start Prometheus
```

**Плюсы:**
- Автоматический запуск
- Работает в фоне
- Перезапуск при сбое

**Минусы:**
- Логи нужно смотреть через Event Viewer

### Рекомендация

**Для разработки:** Вариант 1 (батник)
**Для production:** Вариант 2 (сервис)

## Сколько ресурсов потребляет?

**Prometheus:**
- RAM: ~200 MB
- CPU: 1-2%
- Диск: ~1 GB/месяц (зависит от количества метрик)

**NewsAggregator с метриками:**
- Дополнительно: +5 MB RAM, +0.5% CPU

**Итого:** Почти незаметно для современного компьютера.
