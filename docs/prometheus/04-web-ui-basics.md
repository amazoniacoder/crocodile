## Главная страница

**URL:** http://localhost:9090

### Что здесь есть

**Верхнее меню:**
```
[Prometheus] [Graph] [Alerts] [Status ▼] [Help ▼]
```

**Поле для запросов:**
```
┌─────────────────────────────────────────────────┐
│ Expression (press Shift+Enter for newlines)    │
│ [                                             ] │
└─────────────────────────────────────────────────┘
[Execute] [Add Panel]
```

**Кнопки:**
- **Execute** — выполнить запрос
- **Add Panel** — добавить ещё одну панель для сравнения метрик

## Graph (Графики)

**URL:** http://localhost:9090/graph

Это главная рабочая страница, где ты будешь проводить 90% времени.

### Интерфейс

```
┌─────────────────────────────────────────────────────────────┐
│ Expression: [rate(http_requests_total[5m])              ] │
│ [Execute] [Add Panel]                                       │
├─────────────────────────────────────────────────────────────┤
│ [Table] [Graph]                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│     📈 График здесь                                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Как пользоваться

#### 1. Ввести запрос

Кликни в поле **Expression** и введи:
```promql
nodejs_heap_size_used_bytes
```

Нажми **Execute** (или Enter).

#### 2. Выбрать режим отображения

**Table (Таблица):**
- Показывает текущие значения
- Полезно для проверки точных цифр

**Graph (График):**
- Показывает изменение во времени
- Полезно для анализа трендов

#### 3. Настроить временной диапазон

**Правый верхний угол:**
```
[-] [1h] [3h] [6h] [12h] [1d] [7d] [Custom]
```

Кликни на нужный период:
- **1h** — последний час
- **3h** — последние 3 часа
- **1d** — последние 24 часа
- **Custom** — свой диапазон

#### 4. Управлять графиком

**Zoom (приближение):**
- Зажми левую кнопку мыши и выдели область на графике
- График приблизится к выделенной области

**Reset zoom:**
- Кликни правой кнопкой на графике
- Выбери **Reset zoom**

**Навигация:**
- Используй кнопки `[-]` и `[+]` для изменения масштаба времени

### Автообновление

**Кнопка в правом верхнем углу:**
```
[⟳ 5s] [⟳ 15s] [⟳ 30s] [⟳ 1m] [Off]
```

Выбери интервал автообновления:
- **5s** — обновлять каждые 5 секунд (для мониторинга в реальном времени)
- **Off** — не обновлять автоматически

### Несколько панелей

Кликни **Add Panel** — появится вторая панель с полем для запроса.

**Зачем это нужно:**
- Сравнить две метрики на одном экране
- Например: память и количество запросов

**Удалить панель:**
- Кликни на крестик `[×]` справа от поля Expression

## Targets (Источники метрик)

**URL:** http://localhost:9090/targets

### Что здесь показано

Список всех источников, откуда Prometheus собирает метрики.

### Интерфейс

```
┌─────────────────────────────────────────────────────────────┐
│ news-aggregator (1/1 up)                                    │
├─────────────────────────────────────────────────────────────┤
│ Endpoint                          State    Labels           │
│ http://localhost:5000/metrics     UP 🟢   job=news-agg...   │
│                                   Last Scrape: 2.5s ago     │
│                                   Scrape Duration: 10ms     │
├─────────────────────────────────────────────────────────────┤
│ prometheus (1/1 up)                                         │
├─────────────────────────────────────────────────────────────┤
│ Endpoint                          State    Labels           │
│ http://localhost:9090/metrics     UP 🟢   job=prometheus    │
│                                   Last Scrape: 1.2s ago     │
│                                   Scrape Duration: 8ms      │
└─────────────────────────────────────────────────────────────┘
```

### Статусы

**UP 🟢 (зелёный):**
- Target доступен
- Метрики собираются успешно

**DOWN 🔴 (красный):**
- Target недоступен
- Prometheus не может собрать метрики

**UNKNOWN 🟡 (жёлтый):**
- Prometheus ещё не пытался собрать метрики
- Обычно сразу после запуска

### Детали target

Кликни на **show more** под target — увидишь:

**Discovered Labels:**
- Все метки, которые Prometheus автоматически добавил

**Target Labels:**
- Метки, которые будут добавлены к каждой метрике

**Last Error:**
- Текст последней ошибки (если target был DOWN)

### Что делать, если target DOWN

1. **Проверь доступность:**
   ```bash
   curl http://localhost:5000/metrics
   ```
   Должна открыться страница с метриками.

2. **Проверь логи Prometheus:**
   - Ищи строки с `error` или `failed`

3. **Проверь конфигурацию:**
   ```bash
   promtool check config prometheus.yml
   ```

4. **Подожди 15 секунд:**
   - Prometheus пытается собрать метрики каждые 15 секунд
   - Обнови страницу

## Alerts (Алерты)

**URL:** http://localhost:9090/alerts

### Что здесь показано

Список всех правил алертов и их текущий статус.

### Интерфейс

```
┌─────────────────────────────────────────────────────────────┐
│ news_aggregator_alerts (7 rules)                            │
├─────────────────────────────────────────────────────────────┤
│ HighErrorRate                                               │
│ State: Inactive 🟢                                          │
│ Expression: rate(http_requests_total{status=~"5.."}[5m])   │
│             / rate(http_requests_total[5m]) > 0.05          │
├─────────────────────────────────────────────────────────────┤
│ HighMemoryUsage                                             │
│ State: Pending 🟡 (for 5m 23s)                              │
│ Expression: nodejs_heap_size_used_bytes > 500000000         │
│ Value: 520MB                                                │
├─────────────────────────────────────────────────────────────┤
│ RSSCollectionStalled                                        │
│ State: Firing 🔴 (for 12m 45s)                              │
│ Expression: time() - rss_collection_last_success > 1800    │
│ Summary: RSS сбор не выполнялся более 30 минут              │
└─────────────────────────────────────────────────────────────┘
```

### Статусы алертов

**Inactive 🟢 (зелёный):**
- Условие **не выполнено**
- Всё в порядке

**Pending 🟡 (жёлтый):**
- Условие **выполнено**
- Но ещё не прошёл период `for`
- Алерт ждёт, чтобы убедиться, что это не кратковременный всплеск

**Firing 🔴 (красный):**
- Условие **выполнено** дольше периода `for`
- Алерт **активен**
- Уведомления отправлены (если настроены)

### Детали алерта

Кликни на алерт — увидишь:

**Expression:**
- Запрос PromQL, который проверяется

**For:**
- Сколько времени условие должно быть выполнено

**Labels:**
- Метки алерта (severity, instance, job)

**Annotations:**
- Описание проблемы (summary, description)

**Active Since:**
- Когда алерт перешёл в состояние Firing

**Value:**
- Текущее значение выражения

### Что делать с Firing алертом

1. **Прочитай описание:**
   - Summary и Description объясняют проблему

2. **Проверь метрики:**
   - Скопируй Expression
   - Открой Graph
   - Вставь запрос и построй график

3. **Найди причину:**
   - Посмотри, когда началась проблема
   - Сравни с другими метриками
   - Проверь логи приложения

4. **Исправь проблему:**
   - Перезапусти сервис
   - Освободи память
   - Исправь код

5. **Подожди:**
   - Алерт автоматически перейдёт в Inactive, когда условие перестанет выполняться

## Status (Статус)

**Меню:** Status → выпадающий список

### Runtime & Build Information

**URL:** http://localhost:9090/status

Показывает информацию о Prometheus:
- Версия
- Время запуска (Uptime)
- Путь к конфигурации
- Путь к данным
- Retention период

### Command-Line Flags

**URL:** http://localhost:9090/flags

Показывает все флаги, с которыми запущен Prometheus:
```
--config.file=prometheus.yml
--storage.tsdb.path=data
--storage.tsdb.retention.time=15d
--web.enable-lifecycle
```

### Configuration

**URL:** http://localhost:9090/config

Показывает текущую конфигурацию `prometheus.yml` в YAML-формате.

**Зачем это нужно:**
- Проверить, какая конфигурация сейчас активна
- Убедиться, что изменения применились после hot reload

### Rules

**URL:** http://localhost:9090/rules

Показывает все правила алертов из `alerts.yml`.

**Отличие от /alerts:**
- `/alerts` — текущий статус алертов (Inactive/Pending/Firing)
- `/rules` — список всех правил (даже если они Inactive)

### Targets

**URL:** http://localhost:9090/targets

(Уже описано выше)

### Service Discovery

**URL:** http://localhost:9090/service-discovery

Показывает, как Prometheus обнаруживает targets.

**Для NewsAggregator:**
- Используется `static_configs` (ручная настройка)
- Поэтому эта страница не очень полезна

**Когда полезно:**
- Если используешь автоматическое обнаружение (Kubernetes, Consul, EC2)

### TSDB Status

**URL:** http://localhost:9090/tsdb-status

Показывает статистику базы данных:
- Количество временных рядов (time series)
- Количество блоков данных
- Размер на диске
- Количество samples (точек данных)

**Пример:**
```
Head Stats:
  Number of Series: 150
  Number of Chunks: 450
  Number of Samples: 45000

Block Stats:
  Total Blocks: 12
  Total Size: 150 MB
```

## Полезные советы

### 1. Используй автодополнение

Начни вводить имя метрики в поле Expression:
```
node
```

Появится список всех метрик, начинающихся с `node`:
```
nodejs_heap_size_used_bytes
nodejs_process_cpu_user_seconds_total
nodejs_nodejs_eventloop_lag_seconds
```

Выбери нужную стрелками и нажми Enter.

### 2. Копируй запросы из алертов

Если алерт в состоянии Firing:
1. Открой /alerts
2. Кликни на алерт
3. Скопируй Expression
4. Открой /graph
5. Вставь запрос
6. Построй график

### 3. Сохраняй полезные запросы

Prometheus не сохраняет историю запросов.

**Решение:**
- Создай текстовый файл `useful-queries.txt`
- Сохраняй туда полезные запросы с комментариями

**Пример:**
```
# Память в MB
nodejs_heap_size_used_bytes / 1024 / 1024

# Запросов в секунду
rate(http_requests_total[5m])

# p95 время ответа
histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m]))
```

### 4. Используй несколько вкладок браузера

Открой в разных вкладках:
- `/graph` — для построения графиков
- `/targets` — для проверки статуса
- `/alerts` — для мониторинга алертов

Переключайся между ними по мере необходимости.

### 5. Настрой автообновление

Для мониторинга в реальном времени:
1. Открой /graph
2. Выбери период: **1h**
3. Включи автообновление: **⟳ 15s**
4. Построй график важной метрики

Теперь график будет обновляться каждые 15 секунд.
