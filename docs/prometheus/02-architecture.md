```
┌─────────────────────────────────────────────────────────────┐
│                    NewsAggregator                           │

                            ↓ scrape every 15s

│  │  Time Series Database (TSDB)                         │   │
│  │  - Хранит метрики с временными метками               │   │
```

## Компоненты Prometheus

### 1. Scraper (Сборщик)

**Что делает:**
- Каждые 15 секунд открывает `/metrics` на каждом target
- Парсит текстовый формат
- Записывает данные в TSDB с текущим временем

**Конфигурация:**
```yaml
# prometheus.yml
scrape_configs:
  - job_name: 'news-aggregator'
    static_configs:
      - targets: ['localhost:5000']
    scrape_interval: 15s  # Как часто собирать
    scrape_timeout: 10s   # Максимальное время ожидания
```

**Что происходит при scrape:**
```
14:30:00 → GET http://localhost:5000/metrics
14:30:00 → Получено 150 метрик
14:30:00 → Записано в TSDB с timestamp=1778044200

14:30:15 → GET http://localhost:5000/metrics
14:30:15 → Получено 150 метрик
14:30:15 → Записано в TSDB с timestamp=1778044215

... и так каждые 15 секунд
```

### 2. TSDB (Time Series Database)

**Что делает:**
- Хранит метрики в специальном формате
- Сжимает данные (экономит место)
- Удаляет старые данные (retention)

**Структура данных:**

Каждая метрика — это **временной ряд** (time series):

```
Метрика: http_requests_total{method="GET", path="/api/news"}

Данные:
timestamp=1778044200, value=1520
timestamp=1778044215, value=1523  (+3 за 15 секунд)
timestamp=1778044230, value=1528  (+5 за 15 секунд)
timestamp=1778044245, value=1530  (+2 за 15 секунд)
```

**Хранение на диске:**

```
D:\Prometheus\data\
├── 01HXXX...  (блок данных за 2 часа)
├── 01HYYY...  (блок данных за 2 часа)
└── wal\       (Write-Ahead Log для надёжности)
```

Каждый блок — это 2 часа данных, сжатых в бинарный формат.

**Retention (срок хранения):**

```bash
--storage.tsdb.retention.time=15d
```

Это значит: данные старше 15 дней **автоматически удаляются**.

### 3. Query Engine (Движок запросов)

**Что делает:**
- Выполняет запросы на языке PromQL
- Читает данные из TSDB
- Вычисляет агрегации (sum, avg, rate)
- Возвращает результат для графика

**Пример запроса:**

```promql
rate(http_requests_total[5m])
```

**Что происходит:**
1. Query Engine читает все значения `http_requests_total` за последние 5 минут
2. Вычисляет скорость изменения (requests per second)
3. Возвращает массив точек для графика

### 4. Alert Manager (встроенный)

**Что делает:**
- Каждые 30 секунд проверяет правила из `alerts.yml`
- Если условие выполнено — переводит алерт в состояние `pending`
- Если условие выполнено дольше `for` периода — переводит в `firing`
- Отправляет уведомления через настроенные каналы

**Пример правила:**

```yaml
- alert: HighMemoryUsage
  expr: nodejs_heap_size_used_bytes > 500000000
  for: 10m
```

**Что происходит:**

```
14:30:00 → Проверка: 480MB < 500MB → OK
14:30:30 → Проверка: 520MB > 500MB → pending (начало отсчёта)
14:31:00 → Проверка: 530MB > 500MB → pending (прошло 30 сек)
...
14:40:30 → Проверка: 540MB > 500MB → firing (прошло 10 минут!)
14:40:30 → Отправка уведомления
```

### 5. Web UI

**Что делает:**
- Предоставляет веб-интерфейс на порту 9090
- Позволяет строить графики
- Показывает статус targets и alerts
- Предоставляет HTTP API

**Основные страницы:**

| URL | Назначение |
|-----|-----------|
| http://localhost:9090 | Главная страница |
| http://localhost:9090/graph | Построение графиков |
| http://localhost:9090/targets | Статус источников метрик |
| http://localhost:9090/alerts | Статус алертов |
| http://localhost:9090/config | Текущая конфигурация |
| http://localhost:9090/flags | Флаги запуска |

## Поток данных (детально)

### Шаг 1: Приложение генерирует метрики

**Код в NewsAggregator:**

```typescript
// server/infrastructure/monitoring/PrometheusMetrics.ts
import { Counter } from 'prom-client';

export const httpRequestsTotal = new Counter({
  name: 'http_requests_total',
  help: 'Total number of HTTP requests',
  labelNames: ['method', 'path', 'status']
});

// При каждом HTTP-запросе:
httpRequestsTotal.inc({
  method: 'GET',
  path: '/api/news',
  status: '200'
});
```

**Что происходит:**
- Счётчик `http_requests_total` увеличивается на 1
- Значение хранится **в памяти** приложения
- Ничего не отправляется в Prometheus

### Шаг 2: Prometheus запрашивает метрики

**Каждые 15 секунд:**

```
Prometheus → GET http://localhost:5000/metrics
```

**NewsAggregator отвечает:**

```
# HELP http_requests_total Total number of HTTP requests
# TYPE http_requests_total counter
http_requests_total{method="GET",path="/api/news",status="200"} 1523
http_requests_total{method="POST",path="/api/events",status="200"} 42
...
```

**Формат:**
- `# HELP` — описание метрики
- `# TYPE` — тип метрики (counter, gauge, histogram)
- Далее — имя метрики, метки в `{}`, значение

### Шаг 3: Prometheus сохраняет данные

**Prometheus парсит ответ:**

```
Метрика: http_requests_total
Метки: {method="GET", path="/api/news", status="200"}
Значение: 1523
Время: 2025-05-06 14:30:00 (текущее время Prometheus)
```

**Записывает в TSDB:**

```
time_series_id=12345 (уникальный ID для этой комбинации метрики+меток)
timestamp=1778044200, value=1523
```

### Шаг 4: Ты строишь график

**Ты открываешь Graph и вводишь:**

```promql
rate(http_requests_total{path="/api/news"}[5m])
```

**Prometheus:**
1. Находит все временные ряды с `http_requests_total` и `path="/api/news"`
2. Читает значения за последние 5 минут
3. Вычисляет скорость изменения (requests per second)
4. Возвращает массив точек: `[(14:30:00, 2.5), (14:30:15, 2.8), ...]`
5. Браузер рисует график

## Типы метрик

### Counter (Счётчик)

**Что:** Число, которое **только растёт**.

**Примеры:**
- `http_requests_total` — количество запросов
- `rss_articles_collected_total` — количество собранных статей
- `rss_collection_errors_total` — количество ошибок

**Особенность:**
- Значение **никогда не уменьшается**
- При перезапуске приложения сбрасывается в 0
- Для анализа используется функция `rate()` или `increase()`

**Пример:**

```
14:30:00 → http_requests_total = 1520
14:30:15 → http_requests_total = 1523  (+3)
14:30:30 → http_requests_total = 1528  (+5)
```

**Запрос:**
```promql
rate(http_requests_total[5m])  # Запросов в секунду
```

### Gauge (Датчик)

**Что:** Число, которое **может расти и падать**.

**Примеры:**
- `nodejs_heap_size_used_bytes` — использование памяти
- `cache_size_bytes` — размер кэша
- `rss_collection_last_success_timestamp_seconds` — timestamp последнего сбора

**Особенность:**
- Значение может изменяться в любую сторону
- Показывает **текущее состояние**

**Пример:**

```
14:30:00 → nodejs_heap_size_used_bytes = 130000000
14:30:15 → nodejs_heap_size_used_bytes = 135000000  (+5MB)
14:30:30 → nodejs_heap_size_used_bytes = 120000000  (-15MB, GC сработал)
```

**Запрос:**
```promql
nodejs_heap_size_used_bytes / 1024 / 1024  # Память в MB
```

### Histogram (Гистограмма)

**Что:** Распределение значений по диапазонам (buckets).

**Примеры:**
- `http_request_duration_seconds` — время ответа API

**Особенность:**
- Автоматически создаёт несколько метрик:
  - `_bucket{le="0.1"}` — сколько запросов быстрее 0.1с
  - `_bucket{le="0.5"}` — сколько запросов быстрее 0.5с
  - `_sum` — сумма всех значений
  - `_count` — количество измерений

**Пример:**

```
http_request_duration_seconds_bucket{le="0.1"} 1200  (1200 запросов < 0.1с)
http_request_duration_seconds_bucket{le="0.5"} 1480  (1480 запросов < 0.5с)
http_request_duration_seconds_bucket{le="1.0"} 1520  (1520 запросов < 1.0с)
http_request_duration_seconds_sum 450.5  (сумма всех времён)
http_request_duration_seconds_count 1523  (всего запросов)
```

**Запрос:**
```promql
# 95-й перцентиль (95% запросов быстрее этого значения)
histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m]))
```

### Summary (Сводка)

**Что:** Похоже на Histogram, но перцентили вычисляются на стороне приложения.

**В NewsAggregator не используется** (Histogram предпочтительнее).

## Как Prometheus хранит данные

### Формат на диске

```
D:\Prometheus\data\
├── 01HXXX\
│   ├── chunks\
│   │   └── 000001  (сжатые данные метрик)
│   ├── index       (индекс для быстрого поиска)
│   └── meta.json   (метаданные блока)
├── 01HYYY\
│   └── ...
└── wal\            (Write-Ahead Log)
    ├── 00000000
    └── 00000001
```

**Блоки (Blocks):**
- Каждый блок = 2 часа данных
- Блоки **неизменяемые** (immutable)
- Старые блоки удаляются при достижении retention

**WAL (Write-Ahead Log):**
- Новые данные сначала пишутся в WAL
- Каждые 2 часа WAL превращается в блок
- Защита от потери данных при сбое

### Сжатие данных

Prometheus использует специальный алгоритм сжатия для временных рядов.

**Пример:**

Исходные данные (без сжатия):
```
timestamp=1778044200, value=1520
timestamp=1778044215, value=1523
timestamp=1778044230, value=1528
timestamp=1778044245, value=1530
```

Сжатые данные:
```
base_timestamp=1778044200
base_value=1520
deltas: [+15s, +3], [+15s, +5], [+15s, +2]
```

**Экономия:** ~10x меньше места на диске.

## Масштабирование

### Сколько метрик может хранить Prometheus?

**Типичные цифры:**
- 1 target, 150 метрик → ~10 MB/день
- 10 targets, 1500 метрик → ~100 MB/день
- 100 targets, 15000 метрик → ~1 GB/день

**NewsAggregator:**
- 1 target (сам NewsAggregator)
- ~150 метрик
- Retention 15 дней
- **Итого:** ~150 MB на диске

### Что если метрик станет больше?

**Вариант 1: Увеличить retention**
```bash
--storage.tsdb.retention.time=30d  # Вместо 15d
```

**Вариант 2: Федерация**

Несколько Prometheus серверов, один главный собирает данные с остальных.

**Вариант 3: Remote Storage**

Prometheus отправляет данные в долгосрочное хранилище (Thanos, Cortex, VictoriaMetrics).

**Для NewsAggregator:** Одного Prometheus достаточно.
