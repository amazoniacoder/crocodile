# Subscription Gate — План реализации

> Статус: 🔄 В работе (12/13 задач)  
> Дата: Май 2025  
> Цель: разграничить общий доступ и подписку, создать реальную ценность токена

---

## Концепция

**Общий доступ** (`/social`, `/youtube`) — витринные каналы, ограниченный список, без сохранения настроек.  
**Подписка** (`/my`) — все каналы, персональные инструменты, сохранённые настройки, уведомления.

Разграничение строится на поле `isFeatured` в таблице `news_sources`. Витринные каналы видны всем, остальные — только подписчикам.

## 🔴 Критические

### 1. Поле `isFeatured` в `news_sources`

**Что:** добавить поле `is_featured boolean not null default false` в таблицу `news_sources`.

**Файлы:**
- `shared/schema.ts` — добавить поле в схему Drizzle
- `server/infrastructure/persistence/NewsSourceRepository.ts` — включить в выборки
- `shared/types/news.ts` — добавить в тип `NewsSource`

**Миграция:**
```sql
ALTER TABLE news_sources ADD COLUMN is_featured boolean NOT NULL DEFAULT false;
```

**Начальные данные:** пометить 3–4 канала на каждой платформе (самые активные по количеству статей).

---

### 2. Управление `isFeatured` в админке (`SourcesTable`)

**Что:** добавить колонку «Витрина» в таблицу источников в `ZoneC` с переключателем — только для каналов типа `telegram` и `youtube`.

**Файл:** `client/src/components/admin/monitor/ZoneC/SourcesTable.tsx`

**Изменение:** рядом с `ToggleSwitch` активности добавить второй `ToggleSwitch` для `isFeatured`, видимый только когда `sourceType === 'telegram' || 'youtube'`. При изменении — `adminApi.updateSource(token, id, { isFeatured: next })`.

---

### 3. API: параметр `featuredOnly` в `/api/news`

**Что:** если запрос приходит без токена пользователя и `sourceType` = `telegram` или `youtube` — автоматически фильтровать только `isFeatured = true` каналы.

**Файл:** `server/api/news/index.ts`

**Логика:**
```typescript
// Если sourceType = telegram/youtube и нет userToken — только featured
const featuredOnly = (sourceType === 'telegram' || sourceType === 'youtube')
  && !req.headers['x-user-token'];
```

---

### 4. `SubscriptionGate` — компонент-заглушка

**Что:** новый компонент, который рендерится вместо заблокированных каналов в пикере.

**Файл:** `client/src/components/news/SubscriptionGate.tsx` (новый)

```tsx
// Отображает затемнённый элемент с замком и ссылкой на /my
// Props: count — количество скрытых каналов
```

**Вид:** блок с текстом «+ N каналов доступно по подписке» + кнопка «Получить доступ» → `/my`.

---

### 5. `TelegramChannelPicker` / `YouTubeChannelPicker` — разделение на featured/locked

**Что:** пикер получает список всех каналов, но рендерит:
- `isFeatured === true` → обычный элемент со Switch
- `isFeatured === false` → затемнённый элемент без Switch, с иконкой 🔒

**Файлы:**
- `client/src/components/news/TelegramChannelPicker.tsx`
- `client/src/components/news/YouTubeChannelPicker.tsx`

**Изменение в API:** `/api/telegram/channels` и `/api/youtube/channels` должны возвращать поле `isFeatured` в каждом канале.

**Важно:** заблокированные каналы не участвуют в фильтрации (`enabledChannels` инициализируется только по featured).

### 7. Персональный дайджест `/api/my/digest`

**Что:** сводка за последние 24 часа / 7 дней по подпискам пользователя — топ статей по реакциям + количество новых.

**Файл:** `server/api/my/index.ts` — новый эндпоинт `GET /api/my/digest?period=day|week`

**Клиент:** блок «Дайджест» в шапке `PersonalFeed` — карточка с числом новых статей за период и кнопкой «Показать».

---

### 8. Закладки (сохранённые статьи)

**Что:** пользователь может сохранить статью в закладки — хранятся на сервере, доступны с любого устройства.

**БД:** новая таблица `user_bookmarks (id, token_id, article_id, created_at)`.

**API:**
- `POST /api/my/bookmarks` — добавить
- `DELETE /api/my/bookmarks/:articleId` — удалить
- `GET /api/my/bookmarks` — список

**Клиент:** иконка закладки на карточке статьи в `PersonalFeed` (только на `/my`). Вкладка «Закладки» рядом с TG/YT в шапке `PersonalFeed`.

---

### 9. Web Push только по подпискам

**Что:** сейчас Web Push уведомления приходят при любых новых статьях. Для подписчиков — уведомлять только о новых статьях из их каналов.

**Файл:** `server/services/WebPushService.ts`

**Логика:** при отправке push — проверять подписки токена, фильтровать статьи по `sourceId`.

---

## Что меняется для пользователя

### Без подписки (`/social`, `/youtube`)
- Видит 3–4 витринных канала на каждой платформе
- Пикер каналов показывает заблокированные позиции с замком
- Может запросить добавление канала или сообщить о проблеме через форму обратной связи
- Нет сохранения настроек между сессиями

### С подпиской (`/my`)
- Все каналы без ограничений
- Персональная лента с сохранёнными подписками
- Закладки, дайджест, история чтения
- Web Push только от выбранных каналов
- Персональный RSS-фид
- Индикатор срока действия токена
